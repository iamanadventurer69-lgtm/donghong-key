# 东鸿密钥｜点亮每一度电

面向浙江东鸿电子股份有限公司内部员工的企业文化探索 MVP。**原生微信小程序**，WXML / WXSS / JavaScript + Canvas 2D，不含 H5、WebView、游戏引擎或远程依赖。运行小程序无需 npm 安装或后端服务。

## 快速运行

1. 安装并打开[微信开发者工具（稳定版）](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)。
2. 选择「导入项目」，选择本 README 所在的 `donghong-key` 文件夹，确保目录内有 `project.config.json`。
3. 使用自己的小程序 AppID；只做本地体验可选择工具提供的测试号/游客模式。仓库默认 `appid: touristappid`，若当前工具不接受这个占位值，在导入窗口改选测试号或输入自己的 AppID。
4. 开发模式选「小程序」，后端服务不启用云服务，点击「编译」。代码目录由配置指向 `miniprogram/`。
5. 初始页面为首页。点击「开启文化探索」，依次完成序章和第一章。
6. 真机预览时请使用有权限的真实 AppID，点击开发者工具「预览」后扫码。游客模式的真机能力受工具限制。

项目建议基础库 3.7.0 或以上，使用默认 WebView 渲染模式。所有视觉和模块均本地绘制，不需要配置网络域名、下载素材或构建 npm。

## 已实现

- **首页**：能源网络 Canvas、使命、探索进度、章节状态、愿景、理念与四项价值观。
- **序章**：三段能源故事，显性使命导入，领取使命密钥。
- **第一章「技术之芯」→ 质量值班**：六份材料逐份盖章（放行 / 退回），带客户信任值与四项价值观印记；第一份的选择会在第五份材料里变成后果。
- **第二章「世界之门」→ 认证配对**：把 MID/CE、UL/ETL、SAA/RCM 三张认证卡配到欧盟、北美、澳洲三个市场；配错会抖动并解释，配完三对通过本章。
- **第三章「客户之光」→ 预算组卡**：客户预算三张卡，从六张能力卡里挑组合；缺必需项（回路计量、异常告警）会被客户打回，补上电能质量才是满分组。
- **探索档案**：本机进度、客户信任、四项印记、节点完成状态、文化体系、清档确认、保存失败重试。
- **自动存档**：每次盖章同步保存到本地 storage；未保存行动承诺前不会显示 100%。
- **文化画像**：信任值分档评价 + 四项价值观印记 + 「你的关键行为」（从实际做过的选择里挑影响最大的三条）。
- **闯关中心**：任务轨道（12 项任务，含主线、四个展区打卡、三个小游戏、两个章节小游戏）+ 展区「完成浏览 · 打卡答题」+ 五个小游戏（模块配对 / 能量三消 / 知识答题 / 认证配对 / 方案组卡）+ 全部通关结算（任务清单 + 成绩明细 + GRADE S/A/B）。

第二、三章是独立的可选关卡（NPC 对话 + 判断），答对会把对应价值观记进画像，并各加 10% 进度。值班预计 4–6 分钟，实际时长需员工试用验证。

## 第一章「质量值班」试玩路径

你是计量实验室当天的质量值班员，桌上是六份材料，每份都要盖章：**放行**，或者**退回重测**。

1. 阅读三段序章，领取使命密钥。
2. **第一份 · 今天必须发车**：批次 B-2409 的测试点 B 偏差 +2.4%，超出教学阈值 ±0.5%。退回重测会得罪产线，放行会得罪三个月后的客户。
3. **第二份 · 读数漂移 3%**：现场照片里采样单元和计量核心装反了槽位，判断是装配问题还是环境干扰。
4. **第三份 · 手册里没有这一条**：45℃ 以上才有偏差，而手册只写了常规流程——按手册走，还是补高温工况。
5. **第四份 · 就改成「待定」**：销售要求把 30 台不合格品改成「待定」先发货。
6. **第五份 · 客户回访**：这里的版本取决于你第一份盖了什么——放行过超阈值批次，就会收到批量返修投诉。
7. **第六份 · 要能看双向的电**：预算只够三张能力卡，从六个能力里选三张。
8. 结算：信任值分档 + 文化画像 + 选择一项行动承诺。

设计要点：**没有「错了重试」**。每个选择都会改变客户信任值（0–100，有上下限）和四项价值观印记，选错不会卡住流程，但会留下后果——例如第一份放行，第五份就会变成客户投诉，且结算评语完全不同。判定规则见 `utils/state.js`，数值与文案全在 `data/content.js`。

## 闯关中心（打卡 + 小游戏 + 通关）

首页第 1 屏第 4 张卡进入闯关中心，12 项任务排成两列轨道：

1. **四个展区打卡答题**（文化坐标 / 产品模块 / 价值观 / 走向世界）：读内容 → 点「打卡答题」→ 弹层里选答案，答对才点亮，答错立刻给解释并可以再来一次。
2. **三个小游戏**：
   - 模块配对（翻牌记忆）：16 张牌 8 对，把模块与它的职责、价值观与它的行为配起来；记步数与用时。
   - 能量三消：6×6 棋盘、6 种能源节点，点两个相邻格子交换，三连即消；60 秒计时，连击翻倍，得分写入成绩。
   - 知识答题：10 题共 100 分，每题给解释，答完显示总分与逐题回顾，可以重新挑战（成绩按最后一次算）。
4. **两个章节小游戏**：认证配对（点市场再点认证卡，配错会解释）、方案组卡（预算内挑三张，缺必需项被客户打回）。

3. **全部通关结算**：12 项任务全部完成时自动弹出——任务清单打勾情况、客户信任、配对步数、三消得分、答题分数，以及 **GRADE S / A / B** 评级与评语（S 需要信任 ≥85、答题 ≥80、三消 ≥300、配对 ≤20 步）。

小游戏的判定逻辑（发牌、找三连、下落补牌、是否还有可走的一步）都在 `utils/match3.js`，是不依赖页面的纯函数，可以直接单测。

## 内容与产品边界

企业文化原文来自本次需求。价值观解释、剧情及行动承诺为教学文案，建议由企业文化负责人审阅。

电表外观、模块、电路连接、精度数据、阈值与校准结果都是**简化教学模拟**，不是东鸿真实型号的硬件图、规格、认证参数或维修指导。当前没有引入未核实的成立年份、知识产权数量、认证范围和销售国家数量。Canvas 的网络点亮是剧情效果，不表示其他章节已经开发完成。

## 存档规则

存储键：`donghong.culture.mvp.v1`，当前存档版本 5。只记录「做过什么」：序章位置、每次盖章的选择（decisions）、四个展区的打卡结果、五个小游戏的成绩与答题记录、行动承诺、时间戳。第二、三章的完成状态由「认证配对已配满、方案组卡已通过」推导，不再单独存。

客户信任值与四项价值观印记不存原始数值，而是每次读取时由 decisions 重算（`state.js` 的 `snapshot`）。好处：调数值平衡不用迁移存档；残缺、旧版本或被改过的存档最多停在真正完成过的那一步；结算画像能直接读到玩家自己造成的剧情线。没有姓名、手机号、微信身份或服务器上传。

完成关键动作后立即同步保存，不依赖退出事件。读写失败时显示提示，本次会话保留内存进度，并可到探索档案重试保存。清理微信缓存、更换设备或卸载后不能恢复。

## 游戏设计备忘（参考了哪些机制）

- 线上博物馆式闯关（xTool 创造者之旅那类站点）：**展区打卡答题 + 三合一闯关 + 任务轨道 + 全部通关结算**。本作的闯关中心、进度点、逐题回顾、GRADE 评级都来自这套结构。

- 《死神与税》：**盖章决策**。每份材料两个动作：放行 / 退回，代价写在结果里，不是对错题。
- 《中国式家长》《人生重开模拟器》：**事件卡 + 结算画像**。一屏一张卡，数值累积，最后根据实际行为生成画像与称号。
- 《Reigns 王权》：四个互相拉扯的量表。这里对应守正 / 务实 / 创新 / 精进，可以出现负分，没有“全部满分”的路线。
- 《Papers, Please》：先读材料再盖章，规则手册随时可查，失误会被记录。
- 《奥布拉丁的回归》类的**延迟后果**：第一份放行超阈值批次，第五份材料就变成客户投诉变体。

设计原则：不做「选错了重试」，不做排行榜，不把文化口号直接印在选项上——从行为反推价值观。

## 代码风格与排版

统一风格为：**2 空格缩进、单引号、语句末尾分号、行宽 100 列**（WXML 为 120 列）。
JS / JSON / WXSS 由 Prettier 负责，WXML 由项目自带的 `tools/format-wxml.mjs` 负责。

```sh
npm install            # 只为格式化，开发工具与真机运行都不需要
npm run format         # 按上面的风格重排全部源码
npm run format:check   # 只检查，不写回（提交前跑）
npm run verify         # format:check + check + test 全跑一遍
```

WXML 排版器刻意保守，两条规则不可违背：

1. **文本节点原样保留**——WXML 的 `<text>` 会保留空格与换行，在文本中间插入换行，
   真机上就会多出可见空白。因此含文本的元素即使超过 120 列也不会折行。
2. **只在子节点全是块级元素时折行**，且不在相邻的行内元素（text / image / icon）之间折行，
   避免凭空多出一个影响排版的空白文本节点。

排版器会把这类无法安全折行的情况打印成提示（不影响退出码），需要人工判断时看提示即可。
`npm run format:check` 只检查是否已排版；`node tools/format-wxml.mjs --check` 只检查 WXML。

写作约定：

- 一个文件一个主题，文件顶部用一段注释说明「这个文件负责什么」。
- `data/content.js` 只放文案与数据，`utils/state.js` 只放规则，页面只负责展示与收集操作。
- 变量名写全（`content`、`module`、`touch`），不写 `c`、`m`、`t` 这类缩写；单行只声明一个变量。
- 嵌套三元改成 `if` 早返回；超过三层的 `else if` 拆成独立判断块。

## 动态互动说明

能源网络带沿线光点与核心脉冲；值班页的印章有盖下动画，信任值与印记条实时变化；文化画像的印记条随数值生长。Canvas 动画在页面隐藏或组件卸载时停止。实时实验台组件（负载滑杆 + 波形）已实现但暂未接入新流程，留给后续「复现异常」环节。

## 固定窗口与天蓝主题

所有页面禁用纵向滚动，使用固定视窗分屏。左右滑动空白区域翻页，也可点击底部箭头；上下滑动不会触发翻页。首页 3 屏、序章 3 屏、文化画像 3 屏、探索档案 4 屏；值班页与二三章是一屏一张卡的独立页面。

值班页的手势是**右滑放行、左滑退回**（只有两个动作的卡片才开启手势，三选一的卡片用按钮），误触不会翻页。规则弹层用 `catchtap` 阻止事件穿透。序章前后翻页保存当前故事位置；其他页面回到小程序时根据已保存任务恢复，普通介绍页页码不单独存档。

界面、导航栏、Canvas 电路、波形和动效统一使用天蓝色与白色，并针对较矮视窗压缩间距。原项目目录点击「编译」即可更新；如之前使用解压出的副本，请重新下载新版 ZIP。存档格式未变，无需清空进度。

16 项自动化测试通过，全部 7 个 WXML 模板与 WXSS 编译通过，20 个分屏模板渲染通过。上述检查不替代模拟器与真机的排版验收。
